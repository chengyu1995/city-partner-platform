# 开发团队与测试审核团队交接流程

## 基本原则

开发团队不能把“代码完成”当成“业务完成”。  
任何产品功能必须经过测试审核团队验收后，才能进入老板验收或上线准备。

## 交接流程

1. 开发团队完成任务。
2. Worker 执行静态检查。
3. 开发团队提交 commit 并 push。
4. 项目总管生成开发完成报告。
5. 测试审核团队领取验收任务。
6. 测试审核团队检查页面、流程、数据、权限和异常情况。
7. 测试审核团队输出验收结果。
8. 如有问题，项目总管创建修复批次。
9. 修复完成后再次验收。
10. 通过后才进入老板验收。

## 测试审核重点

- 是否修改了批准范围外的文件。
- 是否破坏已有页面。
- 是否符合老板原始需求。
- 是否存在登录、提交、审核、联系方式泄露风险。
- 是否有可复现的错误。
- 是否需要补充文档。

## 阻止上线规则

以下情况不得上线：
- 未经测试审核。
- 修改范围越权。
- 数据库或环境变量未确认。
- 联系方式未经过审核直接公开。
- 任务报告缺少 commit SHA。
- 页面存在核心流程失败。
