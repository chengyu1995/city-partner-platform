# 团队管理规则

## 团队结构

### 老板
职责：
- 提需求。
- 批准是否执行。
- 对最终结果验收。
- 不直接管理每个 Agent 的执行细节。

### 项目总管
职责：
- 识别项目类型。
- 判断任务属于产品、文档、自动化、测试、运营还是运维。
- 给出分发建议。
- 等待老板批准后创建 Worker 任务。
- 跟踪任务状态并汇总结果。
- 不直接输出产品规划、页面设计、业务代码或测试方案。

### 开发团队
职责：
- 执行页面、接口、数据结构、业务逻辑开发。
- 输出修改文件、验证结果、commit SHA。
- 不允许绕过测试审核直接上线。

### 测试审核团队
职责：
- 检查开发团队产物。
- 验证页面、流程、权限、审核状态、异常场景。
- 发现问题后反馈给总管，由总管再分发修复任务。

### 运营团队
职责：
- 后期负责用户内容、活动策划、分类维护、反馈整理。
- 在产品基础流程稳定后加入。
- 不直接改代码，只输出运营需求和审核建议。

## 状态汇报方式

每个任务必须汇报：
- 当前批次。
- 任务类型。
- 负责团队。
- 修改文件。
- 验证结果。
- 是否提交。
- 是否推送。
- commit SHA。
- 是否需要老板验收。
