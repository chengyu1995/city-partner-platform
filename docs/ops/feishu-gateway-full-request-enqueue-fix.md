# Feishu Gateway Full Request Enqueue Fix

当前项目内没有飞书网关服务端实现文件，因此 BATCH-11 在本仓库只记录网关侧必须修复的入队规则。

## 问题

如果网关把“已接收、正在写入队列”这类机器人回复写入 `hermes_jobs.request_text`，而不是老板原始完整飞书消息，Worker 只能拿到确认语，无法还原真实需求。

这会导致类似 BATCH-10 已接收但没有完整需求正文的问题。

## 必须修复

飞书网关服务器端必须保证：

- `hermes_jobs.request_text` 保存老板原始完整飞书消息。
- 不得把“已接收、正在写入队列”这类机器人回复当作任务内容。
- BATCH-05 到 BATCH-99 都应该支持完整需求入队。
- 入队记录应保留原始消息 ID、发送人、群 ID、时间戳和完整正文。
- 如果需要给老板发确认消息，确认消息只能作为回执，不得覆盖任务正文。

## 建议验收

发送如下飞书消息：

```text
BATCH-11：请执行系统升级阶段……
```

网关写入 `hermes_jobs` 后检查：

- `request_text` 包含完整 BATCH 正文。
- `request_text` 不等于机器人确认语。
- Worker 领取任务时日志里的任务内容是完整需求。

## 回报规则

如果再次发现只有确认语入队，项目总管应向老板回报：

```text
阻塞原因：飞书网关没有保存完整需求正文。
需要老板二选一决策：
A. 先修飞书网关入队规则；
B. 手动重新发送完整需求正文。
```
