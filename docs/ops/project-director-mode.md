# Project Director Mode

项目总管模式用于让 Windows Worker 在收到飞书需求或验收反馈后，先自动诊断和自恢复，再决定是否交给 Codex 修改代码、执行验证、提交并回报。

## 回报口径

总管只向老板回报四类内容：

- 已完成
- 需要老板验收
- 需要老板二选一决策
- 阻塞原因

默认不把 PowerShell、SQL、堆栈日志直接贴给老板。日志只保留在 Worker 本地，回报里只给结论、影响范围和下一步选择。

## 任务前自检

每次任务开始前，Worker 会执行：

- 停止残留的 `next dev`、`next-server`、Turbopack、`npm run dev`、Codex 进程。
- 清理 `.next`、`.turbo`、`node_modules/.cache`。
- 还原 `next-env.d.ts`，并在 `ext-env.d.ts` 存在时一并还原。
- 执行 `git status --short`。
- 自动清理已知生成文件。
- 如果发现未知业务修改，停止执行并回报“发现未确认业务修改”，让老板二选一，而不是要求老板看底层日志。

## Bug 自动诊断

遇到本地页面 500、404、Internal Server Error、Turbopack 缓存错误、端口占用、路径冲突时，总管按以下顺序判断：

1. 缓存问题：优先清理 `.next`、`.turbo`、`node_modules/.cache` 并重启预览。
2. 端口问题：先停旧 dev 服务，再从 3000 自动切到 3001。
3. 路由问题：检查 `/`、`/post`、`/partners` smoke test 结果。
4. 代码语法问题：交给 Codex 执行最小范围修复。
5. 依赖或导入问题：先判断是否是 import 路径或已有依赖使用错误，不自动新增依赖。

涉及密钥、数据库结构、生产部署、删除数据时，总管必须停止并请老板确认。

## 验收反馈处理

老板以后可以直接在飞书发：

```text
验收反馈：/post 点不开
验收反馈：首页样式不好看
验收反馈：partners 报 Internal Server Error
```

总管会自动分类为页面 bug、交互 bug、样式 bug、数据 bug、路由 bug 或本地环境 bug，然后创建修复任务、执行修复、验证和回报。

## 仍需老板确认

以下情况仍然必须老板确认：

- 需要新增或修改密钥。
- 需要改数据库结构、RLS、SQL 或删除数据。
- 需要生产部署。
- 发现未确认业务修改，需要决定保留还是先备份。
- 自动修复连续失败，需要选择扩大修复范围还是指定优先问题。
