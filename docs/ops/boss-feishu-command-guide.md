# Boss Feishu Command Guide

## 老板以后只需要这样说

| 命令 | 用途 |
|---|---|
| `新需求：状态` | 查看项目总管状态、队列和最近任务。 |
| `新需求：查看计划` | 查看最近项目总管计划、任务树或分发状态。 |
| `新需求：帮助` | 查看可用命令和安全边界。 |
| `新需求：我要做一个 xxx 功能` | 提交普通网站需求，先进入项目总管 planning。 |
| `新需求：修改计划：xxx` | 修改当前计划，不直接执行代码。 |
| `总管 批准执行` | 批准最近任务树进入 Worker/Codex 执行。 |
| `总管 暂停` | 暂停新的 Agent 分发。 |
| `总管 恢复` | 恢复新的 Agent 分发。 |
| `验收反馈：xxx 点不开` | 提交点击或交互问题反馈。 |
| `验收反馈：xxx 不好看` | 提交 UI 或视觉反馈。 |
| `验收反馈：xxx 报错` | 提交错误或异常反馈。 |

## 普通需求流程

1. 老板发送 `新需求：我要做一个 xxx 功能`。
2. 项目总管回复需求理解、MVP 范围、任务拆解、多 Agent 分工、风险和建议。
3. 老板可以发送 `新需求：修改计划：xxx` 调整计划。
4. 老板确认后发送 `总管 批准执行`。
5. 项目总管才会把任务分发给 Worker/Codex。
6. Worker/Codex 完成后，项目总管汇总改动、验证、commit hash 和风险。
7. 老板验收；如有问题，发送 `验收反馈：xxx`。

## 哪些会先规划

- 产品功能。
- 页面结构。
- UI/交互建议。
- 前端页面开发。
- 后端接口或数据读写。
- 测试验收。
- 部署或环境检查。

这些内容先进入项目总管 planning，不直接进入 Codex。

## 哪些必须老板批准

- 任何真实代码执行任务。
- 多 Agent Worker 分发。
- 修改业务页面、API、服务端逻辑。
- 修改测试或验收口径。
- 修改运行脚本或基础设施。

## 哪些必须老板额外确认

- 数据库结构、RLS、生产 SQL。
- `.env`、密钥、Vercel 环境变量。
- production deploy。
- 删除数据。
- 大型依赖。
- 恢复 stash 或隔离的业务页面修改。

## 推荐第一条正式产品需求

```text
新需求：启动同城搭子网站 MVP 第一阶段，请项目总管先给我产品计划、页面结构、多 Agent 分工和执行建议，先不要写代码，等我批准后再执行。
```
