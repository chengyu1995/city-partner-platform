## 普通需求流程

1. 老板发送 `新需求：我要做一个 xxx 功能`。
2. 项目总管回复需求理解、MVP 范围、任务拆解、多 Agent 分工、风险和建议。
3. 老板可以发送 `新需求：修改计划：xxx` 调整计划。
4. 老板确认后发送 `总管 批准执行`。
5. 项目总管才会把任务分发给 Worker/Codex。
6. Worker/Codex 完成后，项目总管汇总改动、验证、commit hash 和风险。
7. 老板验收；如有问题，发送 `验收反馈：xxx`。

## 哪些会先规划

- 产品功能。
- 页面结构。
- UI/交互建议。
- 前端页面开发。
- 后端接口或数据读写。
- 测试验收。
- 部署或环境检查。

这些内容先进入项目总管 planning，不直接进入 Codex。

## 短命令优先级

以下短命令必须先于普通网站需求识别处理，并且不得进入 Worker/Codex 队列：

- `新需求：状态`
- `新需求：帮助`
- `新需求：查看计划`
- `新需求：系统自检`
- `新需求：Agent 状态`
- `新需求：Agent 看板`
- `总管 状态`
- `总管 帮助`
- `总管 暂停`
- `总管 恢复`
- `总管 批准执行`
- `选 A`
- `选 B`
- `选择 A`
- `选择 B`
- `批准建议`
- `按 B 做`
- `先做完整产品规划`
- `先做首页 MVP`
- `修改计划：xxx`

其中 `总管 批准执行` 只进入现有审批流程；必须找到最近 planning/task tree，并继续遵守 attempt_id、重复分发和暂停分发防护。

其中 A/B 选择只输出规划并等待老板批准，不会创建 Worker/Codex 执行任务，也不会再次回复同一套 A/B 确认。

## 哪些必须老板批准

- 任何真实代码执行任务。
- 多 Agent Worker 分发。
- 修改业务页面、API、服务端逻辑。
- 修改测试或验收口径。
- 修改运行脚本或基础设施。

## 哪些必须老板额外确认

- 数据库结构、RLS、生产 SQL。
- `.env`、密钥、Vercel 环境变量。
- production deploy。
- 删除数据。
- 大型依赖。
- 恢复 stash 或隔离的业务页面修改。

```text
新需求：启动同城搭子网站 MVP 第一阶段，请项目总管先给我产品计划、页面结构、多 Agent 分工和执行建议，先不要写代码，等我批准后再执行。
```
