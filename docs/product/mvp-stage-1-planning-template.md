# MVP Stage 1 Planning Template

## 老板启动语

```text
新需求：启动同城搭子网站 MVP 第一阶段，请项目总管先给我产品计划、页面结构、多 Agent 分工和执行建议，先不要写代码，等我批准后再执行。
```

## 项目总管必须输出

老板如果回复 `选 B`、`按 B 做` 或 `先做完整产品规划`，项目总管必须直接输出本模板的完整规划，不得再次询问 A/B，也不得写代码。

老板如果回复 `选 A` 或 `先做首页 MVP`，项目总管必须输出首页 MVP 规划，不得再次询问 A/B，也不得写代码。

### 产品目标

- 说明同城搭子网站第一阶段解决什么用户问题。
- 明确本阶段只做 MVP，不扩展复杂运营系统。

### MVP 范围

- 必做范围。
- 暂不做范围。
- 需要老板确认的灰区。

### 用户角色

- 普通用户。
- 发布搭子需求的用户。
- 浏览并联系搭子的用户。
- 后续可能的运营角色。

### 页面清单

- 页面名称。
- 页面目标。
- 关键内容。
- 是否本阶段实现。

### 核心流程

- 浏览搭子信息。
- 发布搭子需求。
- 查看详情。
- 联系或表达兴趣。
- 异常和空状态。

### 多 Agent 分工

- `project_director`：拆解和验收边界。
- `product_manager`：产品计划和页面范围。
- `ui_designer`：视觉和移动端规范。
- `interaction_designer`：流程和状态。
- `frontend_developer`：批准后实现前端。
- `backend_developer`：批准后实现后端/API。
- `testing_engineer`：验收和回归。
- `operations_engineer`：预览、发布和分支检查。

### 执行批次建议

- BATCH-01：产品计划。
- BATCH-02：页面结构和信息架构。
- BATCH-03：UI/交互方案。
- BATCH-04：前端最小实现。
- BATCH-05：后端/API 或 mock 数据边界。
- BATCH-06：验收和发布前检查。

### 风险和待老板确认事项

- 是否需要登录。
- 是否需要真实 Supabase 数据。
- 是否允许用户联系方式展示。
- 是否先做 mock。
- 是否需要运营审核。

## 禁止事项

- 未批准前不得写代码。
- 选择 A/B 后不得再次重复 A/B 确认。
- 选择 A/B 后不得创建 Worker/Codex 执行任务。
- 不得修改业务页面。
- 不得修改数据库结构。
- 不得部署生产。
- 不得恢复 stash 中的业务页面修改。
