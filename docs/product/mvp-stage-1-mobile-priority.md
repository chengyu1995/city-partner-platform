# 同城搭子网站 MVP 第一阶段移动端 375px 信息优先级

## 文档状态

- 阶段：BATCH-P2
- 性质：移动端信息优先级文档，不写 UI 代码
- 视口基准：375px 宽度
- 适用页面：首页 `/`、搭子列表页 `/partners`、发布搭子页 `/post`

## 375px 总原则

- 首屏只放最能帮助用户判断去向的信息。
- 每屏只承担一个主要任务：理解、筛选、浏览、填写或确认。
- 城市、分类、时间、地点、人数属于 P0 信息，不能被长说明挤掉。
- 长说明、预算、注意事项属于 P2 / P3 信息，可放到展开区或更低位置。
- 所有触摸目标建议不小于 44px，高频入口优先放在拇指容易触达的位置。

## 首页移动端优先级

### 首屏 P0

1. 平台定位标题：同城找搭子。
2. 一句副标题：说明吃饭、运动、学习、出游等使用场景。
3. 主行动：去找搭子。
4. 次行动：发布搭子需求。

### 首屏后 P1

1. 城市入口：惠州、广州、深圳、上海。
2. 分类入口：首批 7 类，允许横向滚动或换行展示。
3. 最新 / 推荐搭子预览：最多展示 2-3 条摘要。

### 更低优先级 P2

1. 发布流程说明。
2. 草稿 / 待审核边界提示。
3. 后续城市扩展说明。

### 首页移动端取舍

- 不在首屏展示长列表。
- 不在首屏展示完整风险说明。
- 城市和分类入口应比品牌介绍长文更靠前。

## 搭子列表页移动端优先级

### 顶部 P0

1. 页面标题：同城搭子。
2. 城市筛选。
3. 分类筛选。
4. 当前筛选结果摘要。

### 卡片 P0

1. 标题。
2. 城市 + 分类。
3. 时间。
4. 地点。
5. 人数。

### 卡片 P1

1. 状态：草稿、待审核、已发布等。
2. 简短说明，建议控制在 1-2 行。
3. 查看或继续了解入口。

### 卡片 P2 / P3

1. 标签。
2. 预算说明。
3. 适合人群。
4. 注意事项。

### 列表移动端取舍

- 筛选区应紧凑，避免把列表第一条卡片推到过低位置。
- 卡片不要在 375px 下展示过多字段，优先保留可参与性判断。
- 空状态要直接给“换筛选”或“去发布”入口。

## 发布搭子页移动端优先级

### 表单 P0

1. 城市。
2. 分类。
3. 标题。
4. 时间。
5. 地点。
6. 期望人数。
7. 需求说明。
8. 联系方式类型和联系方式内容。

### 表单 P1

1. 发布人昵称。
2. 适合人群。
3. 预算说明。
4. 注意事项。
5. 保存草稿 / 提交待审核按钮。

### 表单 P2

1. 发布流程解释。
2. 联系方式安全提醒。
3. 本地草稿限制说明。

### 发布页移动端取舍

- 顶部说明控制在 1-2 句，不压缩关键字段。
- 必填字段应早于可选字段。
- 提交按钮和保存草稿按钮应在表单末尾明确区分。
- 校验失败时优先提示第一个未完成的 P0 字段。

## 状态信息移动端优先级

| 状态 | 375px 优先展示 | 可放低或折叠 |
| --- | --- | --- |
| 空状态 | 标题、原因、下一步按钮 | 详细解释 |
| 错误状态 | 发生了什么、重试入口 | 技术原因 |
| 成功状态 | 结果、下一步入口 | 长流程说明 |
| 待审核 | 尚未公开、返回列表入口 | 审核规则详情 |
| 草稿 | 已本地保存、继续编辑入口 | 本地存储限制长说明 |

## 375px 页面顺序建议

### 首页

1. 平台定位。
2. 浏览 / 发布入口。
3. 城市入口。
4. 分类入口。
5. 搭子预览。
6. 发布流程提示。

### 搭子列表页

1. 页面标题。
2. 城市筛选。
3. 分类筛选。
4. 结果摘要。
5. 搭子卡片。
6. 空 / 错误状态。
7. 发布入口。

### 发布搭子页

1. 页面标题和短说明。
2. 城市、分类。
3. 标题、时间、地点、人数。
4. 需求说明。
5. 昵称和联系方式。
6. 可选补充信息。
7. 保存草稿 / 提交待审核。
8. 结果状态。

## BATCH-P3 建议

- 实现 UI 时先用 375px 检查页面顺序，再扩展到 768px 和桌面。
- 列表卡片在移动端应避免一次展示全部字段，必要时用详情页或展开承载低优先级信息。
- 发布页先保证 P0 字段完整、可填写、可校验，再考虑补充字段和视觉强化。
