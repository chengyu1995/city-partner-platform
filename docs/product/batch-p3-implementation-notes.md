# BATCH-P3 实现说明

## 执行批次

- 实际执行批次：BATCH-P3
- 执行范围：首页 `/`、搭子列表页 `/partners`、发布页 `/post` 静态页面结构和本地草稿 / 待审核前端流程
- 数据来源：本地前端 mock 数据和浏览器 localStorage 草稿

## 首页完成内容

- 使用 BATCH-P1 / BATCH-P2 文案实现平台定位、浏览入口和发布入口。
- 展示首批城市：惠州、广州、深圳、上海。
- 展示首批分类：饭搭子、运动搭子、学习搭子、出游搭子、K 歌搭子、摩友搭子、钓友搭子。
- 展示最近搭子预览，数据来自 `src/lib/mock-partners.ts`。
- 保留发布边界提示：填写后先保存为本地草稿或进入待审核，不直接公开联系方式。

## 搭子列表页完成内容

- 支持按城市和分类通过 URL query 静态筛选 mock 搭子需求。
- 卡片展示标题、城市、分类、时间、地点、人数、状态和简短说明。
- 展示空状态和发布入口。
- 展示本机保存的本地草稿 / 待审核预览。
- 联系方式不在列表公开，只保留后续联系方式安全策略扩展口。

## 发布页完成内容

- 实现城市、分类、标题、时间、地点、人数、需求说明、昵称、联系方式等 MVP 字段。
- 实现保存草稿和提交待审核两个前端静态流程。
- 使用本地校验文案提示必填字段。
- 保存成功后展示本地预览和状态反馈。
- 草稿只写入当前浏览器 localStorage，不接真实提交。

## mock 数据说明

- `src/lib/mock-partners.ts` 保存首批城市、首批分类和静态搭子示例。
- `src/lib/local-drafts.ts` 保存本地草稿类型、localStorage 读写、去重、订阅和清空逻辑。
- 当前没有 Supabase 读取或写入。
- 当前没有真实审核后台、登录、个人主页、举报或消息通知。

## 安全边界

- 是否修改数据库：否。
- 是否执行 SQL：否。
- 是否修改 `.env` / `.env.local`：否。
- 是否修改部署配置：否。
- 是否部署：否。
- 是否强制登录：否。
- 是否公开联系方式：否。
