# BATCH-01 产品规划：同城搭子网站首页 MVP

**项目名称**：同城搭子网站  
**阶段目标**：明确首页 MVP 范围，等待老板批准后再进入 UI / 前端开发。  
**当前状态**：产品规划完成，未修改 `src/app/page.tsx`，未进入完整开发，未部署。  

---

## 1. 首页 MVP 范围

首页 MVP 的目标是在用户进入首页后的 5 秒内，让用户明确知道这是一个“同城找搭子”的平台，并能快速进入“找搭子”或“发布搭子”两条核心路径。

### 本阶段必须覆盖

1. 平台定位：清晰表达“同城搭子”，覆盖旅游、K 歌、学习、摩友、钓友等场景。
2. 首屏转化：首屏包含平台标题、一句价值主张、城市入口、找搭子主按钮、发布搭子次按钮。
3. 分类入口：固定展示 5 个分类入口：旅游搭子、K 歌搭子、学习搭子、摩友搭子、钓友搭子。
4. 内容预览：展示少量搭子卡片预览，可以使用静态 mock 数据，不接真实后端。
5. 安全提示：明确提示线下见面注意安全、不提前转账、首次见面建议选择公共场所。
6. 移动端优先：优先保证 375px 手机宽度下可读、可点、不卡顿，同时兼容桌面端。

### 本阶段不做

1. 不做登录、注册、个人主页、发布页的业务逻辑改造。
2. 不做复杂推荐算法。
3. 不接真实后端数据。
4. 不修改数据库结构，不执行 SQL。
5. 不修改 `.env` 或任何生产环境变量。
6. 不部署。
7. 不引入新依赖，除非后续前端开发阶段确认项目现有依赖无法完成基础 UI。

## 3. 用户进入首页后的关键路径

### 路径 A：找搭子

1. 用户打开首页。
2. 首屏看到“同城搭子”平台定位和价值主张。
3. 用户确认或选择城市。
4. 用户点击“找搭子”主按钮，或点击旅游 / K 歌 / 学习 / 摩友 / 钓友分类入口。
5. 用户浏览搭子卡片预览。
6. 后续开发阶段再决定跳转到搭子列表页或详情页。

### 路径 B：发布搭子

1. 用户打开首页。
2. 用户看到“发布搭子”次按钮或发布引导模块。
3. 用户点击发布入口。
4. 后续开发阶段跳转到发布页。
5. 本阶段不改发布页逻辑，只保留入口规划。

### 路径 C：安全认知

1. 用户浏览搭子卡片或发布引导。
2. 页面展示安全提示。
3. 用户明确知道平台建议：线下见面注意安全、不提前转账、首次见面选择公共场所。
4. 后续可扩展为规则页或举报机制，本阶段不实现复杂治理流程。

## 4. UI 风格建议

### 总体方向

- 年轻、轻社交、干净，不做后台系统风格。
- 卡片式布局，圆角明显，留白充足。
- 移动端优先，首屏信息密度适中，避免堆满运营文案。
- 首页应该像“城市生活兴趣入口”，而不是传统信息列表站。

### 视觉建议

| 项目 | 建议 |
|---|---|
| 布局 | 手机端单列布局；桌面端使用居中内容区，分类和卡片可双列或三列 |
| 圆角 | 大模块使用 `rounded-2xl` / `rounded-3xl`，按钮和输入使用 `rounded-lg` |
| 阴影 | 使用轻阴影 `shadow-sm`，卡片 hover 可用 `shadow-md` |
| 配色 | 使用 slate 基础色 + 一个年轻的 accent 色，避免纯黑纯白 |
| 字体 | 使用系统字体，不使用 `next/font/google` |
| 图标 | 使用项目已有 `lucide-react` 图标 |
| 标签 | 城市、分类、时间、人数使用胶囊标签 |
| 头像 | 搭子卡片可使用圆形头像或彩色首字 fallback |
| 触摸目标 | 主要按钮和可点击卡片区域不小于 44px |

### 首屏文案建议

- 标题建议：`找同城搭子，一起出发`
- 价值主张建议：`旅游、K 歌、学习、骑行、钓鱼，找到附近同频的人。`
- 主按钮：`找搭子`
- 次按钮：`发布搭子`
- 城市入口示例：`当前城市：上海`、`切换城市`

## 6. 等待老板批准项

进入 BATCH-02 首页 MVP UI 与前端开发前，建议老板确认：

1. 首页主路径是否按“找搭子优先，发布搭子为次入口”执行。
2. 首页首批分类是否固定为：旅游搭子、K 歌搭子、学习搭子、摩友搭子、钓友搭子。
3. 首页卡片预览是否允许先使用静态 mock 数据，不接真实后端。
4. BATCH-02 是否只实现首页 UI，不改登录、注册、个人主页、发布页业务逻辑。

推荐结论：以上 4 项均确认后，再进入 BATCH-02。这样可以最快验证“用户是否能理解平台并愿意浏览 / 发布搭子需求”，同时避免过早投入聊天、推荐、地图、登录等高成本能力。
