## 1. 首页 MVP 范围

首页首版目标是让新用户在 5 秒内明白这是一个“同城找搭子”的平台，并能立刻进入“找搭子”或“发搭子”两个核心动作。

### 本期包含

1. 首屏定位：清楚说明平台用于寻找同城兴趣伙伴。
2. 城市入口：展示当前城市，并提供城市切换入口。
3. 搭子分类入口：旅游、K 歌、学习、摩友、钓友。
4. 推荐搭子列表预览：展示少量最新或推荐搭子卡片。
5. 发布入口：引导用户发起自己的搭子需求。
6. 安全与信任提示：轻量说明发布需审核、谨慎线下见面。

### 本期不包含

1. 登录注册强依赖。
2. 私信、即时聊天、群聊。
3. 复杂推荐算法。
4. 地图定位和附近实时距离。
5. 支付、会员、置顶推广。
6. 完整后台审核改造。
7. App / 小程序适配。

## 3. 用户进入首页后的关键路径

### 路径 A：找搭子

1. 用户打开首页。
2. 看到首屏标题，确认这是同城搭子平台。
3. 选择城市或沿用默认城市。
4. 点击分类入口或“找搭子”按钮。
5. 进入搭子列表页，按城市 / 分类筛选。
6. 点击感兴趣的搭子卡片。
7. 进入详情页，查看时间、地点、人数、联系方式或报名方式。

### 路径 B：发搭子

1. 用户打开首页。
2. 点击首屏或顶部的“发搭子 / 我要发搭子”。
3. 进入发布页。
4. 填写分类、城市、标题、时间、地点、人数、联系方式。
5. 提交后进入待审核或发布成功反馈。

### 路径 C：从分类快速进入

1. 用户打开首页。
2. 直接点击“旅游 / K 歌 / 学习 / 摩友 / 钓友”。
3. 进入已带分类筛选的列表页。
4. 浏览卡片并进入详情。

## 4. UI 风格建议

### 总体风格

- 移动端优先，先保证 375px 宽度下顺滑浏览。
- 年轻、轻社交、城市生活感，不做后台系统风格。
- 信息密度适中：首页要“能扫一眼”，不要堆满运营文案。
- 视觉上以卡片、圆角、头像、兴趣标签构成社交感。

### 视觉标准

| 项 | 建议 |
|---|---|
| 布局 | 单列移动端布局，桌面端使用居中内容区 + 双列或三列卡片 |
| 圆角 | 大模块 `rounded-2xl` / `rounded-3xl`，按钮和输入 `rounded-lg` |
| 阴影 | 轻阴影 `shadow-sm`，卡片 hover 可用 `shadow-md` |
| 配色 | slate 基础色 + 1 个年轻 accent 色，避免纯黑纯白 |
| 字体 | 系统字体，不使用 `next/font/google` |
| 图标 | 使用已安装的 `lucide-react` 图标 |
| 标签 | 圆角胶囊标签，展示城市、分类、时间、人数 |
| 头像 | 圆形头像或彩色首字母 fallback |
| 触摸目标 | 按钮和可点击卡片区域不小于 44px |

### 首页首屏建议

- 标题直接表达平台定位，例如“找同城搭子，一起出发”。
- 副标题说明场景，例如“旅游、K 歌、学习、骑行、钓鱼，找到附近同频的人”。
- 主按钮优先“找搭子”，次按钮“发搭子”。
- 首屏下方露出分类卡片的一部分，让用户知道可以继续下滑。

- [ ] 首页有清晰的“找搭子”入口。
- [ ] 首页有清晰的“发搭子”入口。
- [ ] 首页展示当前城市，并有城市切换或城市筛选入口。
- [ ] 首页展示 5 个分类：旅游、K 歌、学习、摩友、钓友。
- [ ] 点击分类后进入对应筛选列表或可识别的后续页面。

- [ ] MOCK 模式和真 Supabase 双轨行为不被破坏。

## 6. 建议给老板的确认项

建议老板先确认下面 3 个选择，再进入 UI / 前端开发：

1. 首页首版主路径是否按“找搭子优先，发布为次入口”执行？
2. 首批分类是否固定为：旅游、K 歌、学习、摩友、钓友？
3. 首页是否先使用现有 mock / Supabase 活动数据做卡片预览，不新增复杂推荐逻辑？

推荐答案：全部确认。原因是这能最快验证“用户是否愿意浏览和发布搭子需求”，同时避免一开始做聊天、推荐、地图、登录等高成本功能。
