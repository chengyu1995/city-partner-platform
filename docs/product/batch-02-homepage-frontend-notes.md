# BATCH-02：首页 MVP 前端实现说明

## 本次实现范围

- 重做 `src/app/page.tsx` 首页 MVP。
- 首页移动端优先，桌面端使用双栏首屏与多列分类卡片。
- 入口沿用现有路由：找搭子进入 `/partners`，发布搭子进入 `/post`。

## 首页模块

- 首屏平台定位：同城搭子，覆盖旅游、K 歌、学习、摩友、钓友。
- 价值主张：找到附近同频的人，支持浏览和发布搭子需求。
- 城市入口：默认展示杭州，并提供北京、上海、广州、深圳、杭州、成都快捷入口。
- 核心按钮：找搭子主按钮、发布搭子次按钮。
- 分类入口：固定为旅游搭子、K 歌搭子、学习搭子、摩友搭子、钓友搭子。
- 搭子卡片预览：使用 3 条首页静态 mock 数据。
- 安全提示：线下见面注意安全、不提前转账、首次见面建议选择公共场所。

## Mock 数据说明

本阶段使用页面内静态 mock 数据，仅用于首页搭子卡片预览，不写入数据库，不修改 Supabase 数据访问层。

## 未修改范围

- 未修改数据库结构。
- 未执行 SQL。
- 未修改 `.env`。
- 未引入新依赖。
- 未修改登录、注册、个人主页、发布页业务逻辑。
- 未部署。

## 后续建议

- 若首页卡片需要展示真实内容，可在下一阶段复用现有 `listPartnerPosts` 数据入口。
- 若城市入口需要真实定位，可单独设计城市选择页或筛选组件。
