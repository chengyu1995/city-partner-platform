# BATCH-03：首页交互、跳转与基础验收记录

- 首页文件：`src/app/page.tsx`
- 依据：`docs/product/batch-01-homepage-mvp.md`、`docs/product/batch-02-homepage-frontend-notes.md`

## 跳转检查

### 找搭子

- 首页首屏主按钮“找搭子”跳转到 `/partners`。
- `/partners` 是现有搭子列表页，支持 `category` 和 `city` 查询参数。
- 结论：跳转合理。

### 发布搭子

- 顶部“发布搭子”、首屏“发布搭子”、底部“我要发布搭子”均跳转到 `/post`。
- `/post` 是现有发布搭子页面。
- 结论：跳转合理。

### 城市入口

- 当前城市“杭州”跳转到 `/partners?city=杭州`。
- 热门城市入口跳转到 `/partners?city=<城市名>`。
- 结论：跳转合理，属于列表筛选入口。

### 五类搭子入口

- 旅游、K 歌、学习、摩友、钓友均跳转到 `/partners?category=<分类名>`。
- 移动端首屏下方新增横向分类快捷入口，降低小屏用户寻找分类的成本。
- 结论：五类入口清晰。

### 首页预览卡片

- 首页预览卡片为页面内静态 mock 数据。
- 因静态 mock ID 不保证存在于 `/partners/[id]` 详情页，当前保留跳转到带分类和城市筛选的 `/partners` 列表，避免点击后进入 404。
- 结论：作为首页预览和导流入口合理；若后续改为真实数据，应再切换为详情页跳转。

## 文案检查

- 首屏包含“同城搭子”“附近同频的人”“找旅游、K 歌、学习、摩友、钓友搭子”等定位文案。
- CTA 使用“找搭子”“发布搭子”，与同城搭子平台核心动作一致。
- 安全提示包含线下安全、不提前转账、公共场所见面。
- 结论：文案适合同城搭子定位。

## 移动端检查

- 首页首屏取消移动端强制 `min-h-[92vh]`，仅在 `lg` 及以上保留近一屏首屏高度。
- 移动端分类快捷入口使用横向滚动胶囊按钮，按钮高度不低于 44px。
- 主要 CTA 使用 `min-h-12`，顶部按钮和城市入口使用 `min-h-11`。
- 结论：移动端布局可用，分类入口更容易在小屏被看到。
