# BATCH-22 Choice Routing Notes

## 修复目标

老板回复 `选 A`、`选 B`、`批准建议`、`按 B 做`、`先做完整产品规划`、`先做首页 MVP` 或 `修改计划：xxx` 时，项目总管必须把它识别为上一轮规划确认的选择回复，而不是新的普通网站需求。

## 路由顺序

1. 飞书入口先处理控制台命令。
2. 再处理验收反馈。
3. 再处理 `修改计划：xxx`。
4. 再处理 A/B 选择。
5. 最后才进入普通 `website_product_request` / `system_upgrade_request` 识别。

## 选 B 输出

`选 B`、`选B`、`选择 B`、`按 B 做`、`先做完整产品规划` 会输出完整 MVP 第一阶段规划，包含：

- 产品目标
- 目标用户
- 用户角色
- 页面结构
- 核心流程
- 功能优先级
- 多 Agent 分工
- 执行批次
- 验收标准
- 风险点
- 需要老板确认的问题
- 下一步可回复：`修改计划：xxx` / `总管 批准执行` / `总管 暂停`

## 选 A 输出

`选 A`、`选A`、`选择 A`、`先做首页 MVP` 会输出首页 MVP 规划，包含：

- 首页目标
- 首页模块
- 信息架构
- 交互入口
- 推荐搭子模块
- 发布搭子入口
- 筛选入口
- 多 Agent 分工
- 执行批次
- 需要老板确认的问题

## 安全边界

- A/B 选择只写入 `hermes_messages` planning 记录。
- A/B 选择不会写入 `hermes_jobs`。
- 只有老板之后明确回复 `总管 批准执行`，才会进入 approved execution 分发。
- 本批次不修改业务页面、数据库结构、`.env` 或部署配置。
